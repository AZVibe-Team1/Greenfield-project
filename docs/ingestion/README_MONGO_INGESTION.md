# MongoDB Ingestion Scripts

This directory contains scripts for ingesting test data into MongoDB collections for the Job Portal application.

## Overview

Two ingestion scripts are provided:
- `ingest_mongo_seeker.py` - Ingests job seeker test data into MongoDB
- `ingest_mongo_employer.py` - Ingests employer test data into MongoDB

## Collections

### Seeker Collection
- **seekers**: MongoDB collection storing job seeker documents with personal information, resume, skills, education, and applications

### Employer Collection  
- **employers**: MongoDB collection storing employer documents with company information, contact details, job postings, and received applications

## Running from Docker Compose

### Ingest Test Data

```bash
# Ingest seeker test data
docker compose exec backend uv run python backend/db/ingestion/ingest_mongo_seeker.py

# Ingest employer test data
docker compose exec backend uv run python backend/db/ingestion/ingest_mongo_employer.py
```

## Running Locally (Without Docker)

```bash
# From project root
uv run python backend/db/ingestion/ingest_mongo_seeker.py
uv run python backend/db/ingestion/ingest_mongo_employer.py
```

## Test Data Format

### Seeker Test Data

Create JSON files in `backend/db/mongo_data/seeker/` with the following structure:

**test_seeker_N.json:**
```json
{
  "information": {
    "first_name": "John",
    "last_name": "Doe",
    "email": "john.doe@example.com",
    "phone": "+12025550123",
    "address": {
      "street": "123 Main St",
      "city": "New York",
      "state": "NY",
      "zip_code": "10001"
    }
  },
  "password_hash": "hashed_password_123",
  "education_level": "MS",
  "edu_focus": "Computer Science",
  "pay_range": [80000, 120000],
  "pay_unit": "Yearly",
  "key_skills": ["Python", "FastAPI", "MongoDB"],
  "resume": "Full resume text here..."
}
```

**Required Fields:**
- `information` (object): Personal and contact information
  - `first_name` (string)
  - `last_name` (string)
  - `email` (string, unique)
  - `phone` (string, E.164 format)
  - `address` (object)
- `password_hash` (string)
- `education_level` (string): BA, BS, MA, MS, MBA, or PhD
- `edu_focus` (string): Field of study

**Optional Fields:**
- `pay_range` (array of 2 integers): Defaults to [0, 0]
- `pay_unit` (string): Hourly, Monthly, or Yearly (default: Yearly)
- `key_skills` (array of strings): Max 15 skills
- `resume` (string): Resume text content

### Employer Test Data

Create JSON files in `backend/db/mongo_data/employer/` with the following structure:

**test_employer_N.json:**
```json
{
  "company_information": {
    "company_name": "Tech Corp",
    "address": {
      "street": "456 Business Ave",
      "city": "San Francisco",
      "state": "CA",
      "zip_code": "94105"
    },
    "industry": [
      {
        "code": "45",
        "description": "Information Technology"
      },
      {
        "code": "4510",
        "description": "Software & Services"
      }
    ],
    "benefits": "Health insurance, 401k, Remote work"
  },
  "contact_first_name": "Jane",
  "contact_last_name": "Smith",
  "email": "jane@techcorp.com",
  "password_hash": "hashed_password_456",
  "open_jobs": [
    {
      "job_title": "Software Engineer",
      "job_description": "Full job description...",
      "department": "Engineering",
      "hire_mgr_first": "John",
      "hire_mgr_last": "Doe",
      "pay_range": [100000, 150000],
      "pay_unit": "Yearly",
      "education_level": "BS",
      "edu_focus": "Computer Science",
      "key_skills": ["Python", "FastAPI", "Docker"]
    }
  ]
}
```

**Required Fields:**
- `company_information` (object)
  - `company_name` (string, unique)
  - `address` (object)
  - `industry` (array of 2 objects): GICS codes with descriptions
- `contact_first_name` (string)
- `contact_last_name` (string)
- `email` (string, unique)
- `password_hash` (string)
- `open_jobs` (array): Can be empty array

**Job Posting Fields (in open_jobs array):**
- `job_title` (string)
- `job_description` (string)
- `department` (string)
- `hire_mgr_first` (string)
- `hire_mgr_last` (string)
- `pay_range` (array of 2 integers)
- `pay_unit` (string): Hourly, Monthly, or Yearly
- `education_level` (string): BA, BS, MA, MS, MBA, or PhD
- `edu_focus` (string)
- `key_skills` (array of strings): Max 15 skills

## Features

### Duplicate Detection

Both scripts automatically detect and skip duplicate records:
- **Seekers**: Checked by email address
- **Employers**: Checked by both email address and company name

If a duplicate is found, the script logs a warning and skips that record without failing.

### Automatic ID Generation

- **seeker_id / employer_id**: MongoDB ObjectId (automatically generated)
- **seeker_identification / employer_identification**: UUID (automatically generated by schema)
- **job_id / job_identification**: Generated for each job posting
- **temperature**: Default value 0.75 (automatically set by schema)

### Validation

All data is validated against Pydantic schemas before insertion:
- Phone numbers must be in E.164 format (e.g., `+12025550123`)
- Email addresses must be valid
- State codes must be valid 2-letter US state abbreviations
- ZIP codes must be valid US zip codes
- GICS industry codes must be valid (2, 4, 6, or 8 digits)
- Education levels must be one of: BA, BS, MA, MS, MBA, PhD
- Pay units must be one of: Hourly, Monthly, Yearly

## Integration with Existing Infrastructure

These scripts use the existing backend infrastructure:

### CRUD Operations
- `backend.db.seeker_db_ops.SeekerCRUD.create_seeker()`
- `backend.db.employer_db_ops.EmployerCRUD.create_employer()`

### Database Connection
- `backend.db.settings.connect_to_mongodb()`
- `backend.db.settings.close_mongodb_connection()`

### Schemas
- `backend.schemas.seeker.Seeker`
- `backend.schemas.employer.Employer`

## Relationship with ChromaDB Ingestion

These MongoDB scripts focus solely on ingesting data into MongoDB. For ChromaDB ingestion:
- Use `ingest_seeker.py` and `ingest_employer.py` for ChromaDB
- The application's service layer (`seeker_services.py`, `employer_services.py`) handles automatic ChromaDB writes during normal operations

## Troubleshooting

### Path Issues in Docker

The scripts automatically detect if running in Docker and adjust paths accordingly:
- Local: `./backend/db/mongo_data/`
- Docker: `/app/backend/db/mongo_data/`

### MongoDB Connection

Ensure MongoDB is accessible and environment variables are set in `.env`:
```
MONGO_DB_USER=your_user
MONGO_DB_PASSWORD=your_password
MONGO_DB_URL=mongodb+srv://...
MONGO_DB_NAME=job-portal
```

### Validation Errors

If ingestion fails with validation errors, check that your test data matches the schema requirements listed above.

### Duplicate Records

If you need to re-ingest data, either:
1. Delete existing records from MongoDB first
2. Modify the email addresses in your test JSON files to be unique

## Example: Complete Workflow

```bash
# 1. Start Docker containers
docker compose up -d

# 2. Ingest MongoDB test data
docker compose exec backend uv run python backend/db/ingestion/ingest_mongo_seeker.py
docker compose exec backend uv run python backend/db/ingestion/ingest_mongo_employer.py

# 3. Ingest ChromaDB test data (optional, for vector search)
docker compose exec backend uv run python backend/db/ingestion/ingest_seeker.py --test-data
docker compose exec backend uv run python backend/db/ingestion/ingest_employer.py --test-data

# 4. Verify data
docker compose exec backend uv run python -c "
import asyncio
from backend.db.settings import connect_to_mongodb, close_mongodb_connection
from backend.db.seeker_db_ops import SeekerCRUD
from backend.db.employer_db_ops import EmployerCRUD

async def verify():
    await connect_to_mongodb()
    seekers = await SeekerCRUD.count_seekers()
    employers = await EmployerCRUD.count_employers()
    print(f'Seekers: {seekers}, Employers: {employers}')
    await close_mongodb_connection()

asyncio.run(verify())
"
```

## Notes

- Scripts use async/await due to Beanie ODM requirements
- All timestamps use America/Denver timezone
- Scripts exit with code 0 on success, 1 on any failures
- Duplicate detection prevents re-inserting the same test data
- Job postings are embedded within employer documents
